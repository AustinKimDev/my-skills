# Image generation runtime integration

Use this guide for the calling skill's authorized raster generation or editing. The bundle contains the production workflow; the active environment must supply an image tool. No separate `imagegen` skill installation is required. If the environment provides that skill or provider instructions, follow them for tool-specific mechanics without changing the requested scope.

1. Distinguish a new image, a reference-guided generation, and an edit of an existing image. Inspect every edit target first. Identify each supplied image's role; specify what must remain unchanged and the bounded requested alteration.
2. Use the user's selected backend, otherwise the exposed built-in image tool. Read its actual input schema. Do not assume a model selector, destination parameter, mask facility, batch API, or filesystem reference mechanism that the tool does not expose. Tool and environment instructions take precedence over this portable guide.
3. Supply the subject, exact visible copy, intended dimensions/composition, inspected references, style constraints, and background/alpha requirement. Request a transparent background for cutouts and preserve existing transparency during edits unless changing it was requested. Use the reference mechanism supported by that tool.
4. Generate separate deliverables with separate calls. Run independent calls concurrently when the harness supports it, subject to the user's budget and concurrency limits. Inspect an anchor before dependent variants. Parallel image calls do not authorize subagents or a paid API/CLI.
5. Wait for actual completion through the tool's supported lifecycle. Distinguish pending, failed, and completed outputs. Do not announce a saved file, model, image dimension, or background transparency that the returned result does not establish.
6. Inspect the result for exact copy, composition, requested edits, reference consistency, dimensions, and transparency where relevant. Correct demonstrated defects within the authorized batch. Use the image tool for image editing unless the user or active environment explicitly permits another method; this guide does not override backend editing restrictions.
7. Save the selected result into the task or project location before referencing it in an artifact. Use returned files or the documented export mechanism; never invent a cache path. Keep the original and create a versioned sibling unless replacement was authorized. Record the actual prompt, reference roles, source identifier, saved path, and material verification limits.

When a required tool is unavailable or fails, continue catalog/layout work using existing authorized assets and keep new images pending. Name the missing capability. Do not silently substitute code-rendered mockups or another provider when the user selected raster generation. A new account, API key, tool installation, paid backend, or larger batch is a separate decision; never expose credentials in output or provenance.

Return saved paths and actual evidence to the calling workflow. A generated picture does not establish product implementation, component integration, authentication, or payment behavior.
