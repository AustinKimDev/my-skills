화면 번호와 연결된 명세

요구사항·정책·검수 기준은 같은 식별자로 연결됩니다. 기준 버전: SF-1.

SF-01 · 저장 시작과 반복 실행

  • 조건: 변경된 유효한 입력이 있고 기존 편집 권한이 유지됨.
  • 행동: 저장 선택 → 처리 중 상태. 입력과 저장 재실행을 잠시 막고 버튼에 “저장 중”을 표시한다.
  • UI 규칙: 포커스가 사라지거나 다른 버튼으로 임의 이동하지 않게 한다. 처리 중 상태를 보조기술에도 전달한다.
  • 예시 정책 P-SF-01: 처리 중인 동일 작업을 반복 실행하지 않는다.
  • 검수 AC-SF-01: 처리 중 다시 활성화를 시도해도 추가 작업이 시작되지 않으며 현재 입력은 유지된다.
Markdown 기준 명세 · 화면으로 돌아가기

SF-02 · 성공

  • 조건: 저장 성공이 확인됨.
  • 결과: 같은 화면에서 “저장했어요.”를 표시하고 편집을 다시 허용한다. 저장된 값을 기준으로 변경 여부를 판단한다.
  • 정책 P-SF-02: 결과를 알리기 위해 자동으로 다른 화면으로 이동하지 않는다.
  • 검수 AC-SF-02: 성공 후 기존 입력이 보이고, 추가 수정이 없으면 저장을 다시 실행하지 않는다.

SF-03 · 적용되지 않은 실패가 확인됨

  • 조건: 작업이 적용되지 않았다는 결과가 확인됨.
  • 결과: 입력을 유지하고 “저장하지 못했어요. 입력한 내용은 그대로예요.”와 “다시 저장”을 제공한다.
  • 정책 P-SF-03: 수정 후 재시도도 가능하다. 실패 이유가 확인되지 않았다면 원인을 단정하지 않는다.
  • 검수 AC-SF-03: 실패 직전의 입력으로 돌아와 수정·재시도할 수 있고, 재시도에도 처리 중 규칙이 적용된다.
Markdown 기준 명세 · 화면으로 돌아가기

SF-04 · 결과를 아직 알 수 없음

  • 조건: 응답 유실 등으로 적용 여부를 판정할 수 없음. 이를 SF-03의 확정 실패로 취급하지 않는다.
  • 결과: “저장 결과를 확인하지 못했어요.”와 “결과 확인”을 표시한다. 확인 전까지 같은 작업의 새 저장과 편집을 보류한다.
  • 정책 P-SF-04: 결과 확인은 저장을 다시 실행하는 동작이 아니다. 성공 확인 → SF-02, 미적용 확인 → SF-03, 여전히 미확인 → 현 상태 유지.
  • 검수 AC-SF-04: 결과 확인을 해도 저장 작업이 중복 실행되지 않으며, 미확인 상태에서 무조건 재시도를 안내하지 않는다.
  • 후속 확인: 현재 제품이 이전 저장의 결과를 구분할 수 있는지 개발 확인이 필요하다. 불가능하면 이 경로의 복구 정책을 다시 합의해야 한다. 새로운 API는 이 예시에서 정하지 않는다.
Markdown 기준 명세 · 화면으로 돌아가기

SF-05 · 상태 이해와 복귀

  • 라벨은 저장·저장 중·다시 저장·결과 확인을 구분한다. 상태를 색상으로만 전달하지 않는다.
  • 키보드로 입력·저장·복구를 사용할 수 있어야 한다. 상태가 바뀌어도 입력과 버튼의 읽는 순서는 유지한다.
  • 제품 화면의 뒤로가기는 기존 경로를 따른다. 처리 중 화면을 떠나는 행위는 저장 취소를 의미하지 않는다. 재진입하면 저장된 값과 남아 있는 작업의 결과를 확인한다. 미완료 작업의 결과가 불명확하면 SF-04를 적용하고, 결과를 확정한 뒤 편집을 허용한다.
  • 검수 AC-SF-05: 키보드 사용과 상태 안내를 실제 대상 환경에서 확인한다. HTML 예시 통과만으로 제품 접근성·재진입 동작을 통과 처리하지 않는다.
