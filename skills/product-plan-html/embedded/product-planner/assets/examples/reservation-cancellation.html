S-ADMIN · 운영자 조회 6

회의실 A · 예시 예약

예약됨

예시는 같은 로컬 상태를 즉시 보여줍니다. 실제 갱신 지연과 미확인 문의 처리 수단은 별도 확인합니다. 시작 후 예외 취소 권한은 추가하지 않습니다.

검증과 인계 전 확인

연결 검수: 정상 취소, 확인 전 예약 유지, 확정 시 시간 경계, 실패 후 재시도, 결과 확인, 목록·운영 조회 상태 일치를 확인합니다.

제품에서 확인할 경로: 권한 차단, 화면을 닫은 뒤 재진입, 서비스 시각과 시간대, 실제 결과 확인의 최종성·조회 지연. 이 로컬 예시는 해당 구현을 증명하지 않습니다.

실제 효과 미검증: 운영 문의 감소와 취소 편의성은 가설입니다. 실제 기준치·대상·관찰 기간을 정한 뒤 검증해야 합니다.

화면 번호와 연결된 명세

요구사항·정책·검수 기준은 같은 식별자로 연결됩니다. 기준 버전: RC-1.

RC-01 · 자격과 노출

  • 정책 P-RC-01: 예약자는 본인 예약에 한해 시작 전에 직접 취소할 수 있다. 정확히 시작 시각부터는 불가하다.
  • S-DETAIL에는 예약명·시작 시각·현재 상태와 취소 가능 여부를 함께 표시한다. 취소 불가 시 “예약 시작 후에는 취소할 수 없어요.”를 제공한다.
  • 검수 AC-RC-01: 시작 전·정확히 시작·시작 후를 구분해 확인한다. 버튼 숨김 여부만으로 권한 차단을 검증하지 않는다.

RC-02 · 취소 확인과 처리 중

  • S-CONFIRM은 대상 예약, 취소 결과, “예약 유지”와 “예약 취소”를 제공한다. 확정 전 복귀는 예약 상태를 바꾸지 않는다.
  • 확정하면 처리 중 표시와 반복 실행 차단을 적용한다. 이 예시에서는 확인 화면 안의 동작을 잠시 막는다. 브라우저·앱 자체를 닫는 행위까지 막는다고 약속하지 않는다.
  • 정책 P-RC-02: 화면을 닫았다고 진행 중 취소가 철회되지는 않는다. 재진입 시 예약 상태부터 확인한다.
  • 검수 AC-RC-02: 확인 전 예약 유지로 상세에 복귀 가능. 처리 중 추가 취소가 시작되지 않음. 재진입 경로는 실제 제품에서 별도로 확인.

RC-03 · 완료와 연결 화면

  • 성공이 확인되면 “예약을 취소했어요.”와 취소됨 상태를 표시한다. 예약 목록으로 돌아가도 취소됨으로 보인다.
  • 정책 P-RC-03: 취소는 되돌리지 않는다. 이미 취소된 예약을 재취소해도 중복 부수효과가 생기지 않아야 한다.
  • 검수 AC-RC-03: S-DETAIL·S-LIST·S-ADMIN의 동일 예약 상태가 일치하며, 오래된 화면 재시도는 취소됨으로 정리된다.

RC-04 · 시간 경계와 경쟁 상황

  • 취소 확정 시점의 최종 조건을 다시 판정한다. 상세를 시작 전에 열었다는 이유로 시작 이후 취소를 허용하지 않는다.
  • 거절 시 예약 상태를 유지하고 원인을 안내한다. 다시 취소 버튼을 제공하지 않는다.
  • 검수 AC-RC-04: C-02·C-05에서 예약됨이 유지된다. 서비스 시각의 기준과 표시 시간대는 실제 프로젝트 규칙 확인이 필요하다.

RC-05 · 실패·미확인·재시도

  • 미적용 실패가 확인되면 “취소하지 못했어요. 예약은 유지돼요.”와 재시도를 제공한다. 재시도는 현재 자격을 다시 평가한다.
  • 결과 미확인이면 “취소 결과를 확인하지 못했어요.”와 결과 확인을 제공한다. 미확인이라는 이유로 예약 유지 또는 취소 완료라고 단정하지 않는다.
  • 결과 확인으로 취소됨 확인 → RC-03, 예약됨 확인 → 현재 시간 조건에 맞는 화면, 여전히 미확인 → 현 안내 유지.
  • 검수 AC-RC-05: 결과 확인은 새 취소를 실행하지 않는다. 반복 활성화·결과 미확인 지속·시간 경계 경과도 확인한다.

RC-06 · 운영 영향

  • 기존 관리 권한을 가진 운영자는 같은 예약 상태를 조회한다. 이 변경은 시작 후 강제 취소 권한을 부여하지 않는다.
  • 운영자가 미확인 문의를 받으면 확인 가능한 예약 상태를 기준으로 안내한다. 조회할 수 없다면 해결됐다고 말하지 않는다. 새 지원 채널·응답 시간은 약속하지 않는다.
  • 검수 AC-RC-06: 운영자 조회와 사용자 목록·상세가 동일 예약 상태를 설명한다. 갱신 지연이 있다면 확인 시각을 구분하고 실제 허용 지연을 추가 합의한다.
