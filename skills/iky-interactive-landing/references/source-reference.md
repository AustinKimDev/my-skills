# Yumeit reference and adaptation boundary

Reference: [public introduction website](https://yumeit.me/) and
[experience section](https://yumeit.me/#experience), inspected on 2026-10-03.
This package extracts a design/workflow, not a frozen service copy or an
affiliation claim for another product using it.

## What defines this version

- Near-black/violet/lavender editorial composition and large Korean headings.
- A square portrait card, orbital motif and floating tag in the hero.
- Three readable HTML demos: post, recruitment/team and schedule/checklist.
- Specific community, preparation, schedule, booking and used-item compositions.
- Matching explanation highlights and single-open mobile disclosures, preserving
  controls/focus when the same DOM moves across the breakpoint.
- Desktop measured chapters, manual mobile tabs/swipes, separate reading/chapter
  progress, controlled ambient loops and a seamless word strip.
- Distinct editorial photos, independent FAQs, a compact mobile menu, clear
  prelaunch status and quiet policy/support pages.

## Superseded directions

Do not accidentally restore small phone-screen fans, screenshot enlargement and
its large trigger, mobile pinning, a seven-item mobile contents row or one repeated
portrait for every story. Static mobile card stacks were replaced by adjacent
explanation/example disclosures. These decisions govern close reproduction of
this reference, not unrelated projects that explicitly choose those patterns.

The lowercase wordmark and eight-ray symbol belong to Yumeit's identity. Use the
target product's own mark. Inside Yumeit, use canonical vectors, not a Unicode
asterisk or recreated geometry. This package contains no logo, private settings,
user data, policy text, source screenshot or photographic asset.

## Original implementation

The Yumeit site is an Astro project (observed: Astro 7.3.5, Motion 13.4.6,
Lenis 1.3.26) with separate controllers for chapters, matching highlights,
ambient loops and smooth scrolling. These are provenance notes, not installation
instructions or version pins; preserve the destination stack and verify its APIs.

Extraction inspected the public desktop experience screen and current source/design
records. The session browser could not resize its viewport; mobile behavior here
comes from source and the project's recorded checks, not a new mobile-device test.
Every new implementation still needs its own scoped visual/behavioral verification.
