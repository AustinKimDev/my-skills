# Dashboards and operational tools

Overview, analytics, records, review, workflow, editing, and access are optional task lenses. [Catalog entries](catalog.json) are examples, not a limit: maps, canvases, timelines, simulations, and hybrid workspaces may serve the task better.

Establish role, task frequency, decisions, accuracy needs, and access requirements. Do not add sidebars, KPI cards, or charts simply because this is an admin interface.

## Connections

Examples: overview → analytics → records → record-detail → workflow; record-detail → editor → record-detail; workflow → chat.channels. Preserve selected records and filters. Do not expose permission-management features to everyone as a workaround for denied access.

## Comparisons

Compare meaningful work patterns: table-first, summary plus queue, contextual details, grouped tasks, or progressive disclosure. Follow the shared five-alternative policy; do not copy these patterns as a fixed menu. Component comparisons may isolate filters, rows, toolbars, legends, and status indicators. Typography uses identical numbers, units, and long names. Prototype comparisons cover filter → selection → action → result/recovery.

## Checks

Use better-layout, better-typography, and better-accessibility as needed. Choose charts from actual questions and data structures. State units, aggregation period, timestamps, incomplete/stale data, and sample status. Never manufacture KPI claims. Verify batch scope/results, conflicts, permissions, and retries. On narrow screens, retain required comparisons or a usable detail path rather than hiding essential information.
